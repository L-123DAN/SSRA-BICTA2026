# Phase 2 execution plan and fixed support sets

Prepared while Phase 1 continued; no Phase 2 GPU work was started before Phase 1 completion.

- Fixed categories: cashew, candle, capsules, pcb1, macaroni1, pipe_fryum.
- Existing 1-shot results: 30/30 verified against original fixed-final artifacts and reused.
- New settings: 2-shot and 4-shot × support seeds 3407, 42, 2026, 123, 2024; 60 new runs.
- Training seed 111, 100 epochs, fixed-final, batch size 4, same ViT-B-16-plus-240/laion400m_e32 backbone, same PromptAD source commit `0f86ce0dc1ed59007d51348d8d566aed31360cf9` and same evaluation pipeline.
- Deterministic support sets come from existing `splits/visa_1cls_shot{2,4}_supportseed{seed}.json`, generated by the project split builder using `random.Random(f"{seed}:{category}").sample(normal_train, shot)` after sorting official normal training paths. The sets are nested across shot counts for a given category/seed. `results/csv/shot_support_manifest.csv` records all 60 combinations and full paths. Input validation found 60/60 support sets with distinct images, each in the official normal training split and outside the exact official test split.
- The runner writes `results/csv/shot_sensitivity_raw.csv` atomically after every complete pair; it verifies config, runtime, 100 finite training losses, final checkpoint, metric CSV, AUPRO artifact, and source split before reuse. Failed attempts are retained in `docs/shot_sensitivity_failures.md` and individual logs. No run is repeated because of its metric.
- Only after Phase 1 reaches 60/60 and passes independent artifact verification will `scripts/continue_research_pipeline.py` call `scripts/run_shot_sensitivity.py`.
- A command-template audit compared all 120 planned classification/segmentation commands with the verified 1-shot runner after normalizing only `--k-shot` and the output directory. Every remaining argument matched exactly. This check launched no GPU job.
- A further `--validate-only` check during the running pcb2 Phase 1 pair reconfirmed the 30/30 reusable 1-shot artifacts and all 60 planned new support sets. It launched no Phase 2 training process.
- Before Phase 2 launch, progress and failure-log appends were serialized with a process-local lock. This addresses an observed missing START line in the Phase 1 summary progress log from two simultaneous worker threads; the underlying per-task logs and experiment artifacts were present. The Phase 2 support selection, commands, metrics, and retry protocol were unchanged. The updated `--validate-only` path passed.
- Timing caveat observed during execution: `candle` 4-shot seed `42` completed successfully, but its AUPRO subprocess recorded 15,470.19 wall seconds between its 05:49 start and 10:07 finish while the machine was inactive for several hours. Its classification and segmentation runtimes, metrics, checkpoint, and AUPRO artifact are valid. The raw timing remains unmodified; the final audit flags this outlier and does not call summed wall durations GPU busy time.
- A second host-inactivity interval affected `capsules` 4-shot seed `2024`: both concurrent classification and segmentation subprocesses started at 12:17 and recorded 10,715.01 and 10,748.37 wall seconds. The pair later completed successfully with its final artifacts; its raw timing also remains unmodified. The final audit should flag both subprocess durations and interpret summed wall times accordingly.
