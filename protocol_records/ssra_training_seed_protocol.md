# SSRA training-seed protocol

The 1-shot VisA full factorial uses categories `candle`, `pcb1`, `cashew`; existing support seeds `3407, 42, 2026, 123, 2024`; and training seeds `111, 222, 333`. The 15 existing seed-111 cells are reused after artifact verification. The 30 seed-222/333 cells use the same indexed VisA split, same PromptAD source commit `0f86ce0dc1ed59007d51348d8d566aed31360cf9`, CLIP ViT-B-16-plus-240/laion400m_e32, batch size 4, optimizer and learning-rate schedule, 100 epochs and **fixed-final** checkpoint. Classification and segmentation are separate official PromptAD processes; final AUPRO uses the final segmentation checkpoint. No official-best or test-metric checkpoint choice is allowed.

The official `utils.training_utils.setup_seed(seed)` is called at the start of each official classification/segmentation `main` before DataLoader/model construction. It sets `torch.manual_seed` (CPU RNG), `torch.cuda.manual_seed_all` (CUDA RNGs), `numpy.random.seed`, `random.seed` and `torch.backends.cudnn.deterministic=True`. Each scientific cell passes its explicit training seed to both processes via `scripts/run_promptad.py`. Prompt context initialization uses `nn.init.normal_`, hence the seeded PyTorch RNG. The official training DataLoader uses `shuffle=True`, `num_workers=0`; PyTorch's sampler runs in the same seeded process. With one support, no alternative support order exists, but DataLoader RNG consumption can still occur. The official optimizer and cosine schedule themselves are deterministic functions of their initialized state and input order; any stochastic CUDA operation would draw from the seeded CUDA RNG.

Controls have limits. The official source does **not** call `torch.use_deterministic_algorithms(True)` or set `CUBLAS_WORKSPACE_CONFIG`; its `setup_seed` sets cuDNN deterministic mode but does not explicitly disable cuDNN benchmark mode. CUDA library kernels, parallel reductions, hardware/driver/library updates and worker-independent external state may prevent bitwise repeatability. SSRA therefore labels these as controlled **seed conditions**, not a proof of bitwise deterministic outcomes. Software, runtime config, final checkpoint, losses, execution time and GPU memory are recorded for each run. Technical failure permits only a retry with the identical command and configuration, with the failed attempt and reason retained.

The fixed-final wrapper masks intermediate test metrics and allows a metric/checkpoint write at epoch 100 only; it leaves official training and forward/backward code unchanged. Intermediate test passes still occur, matching prior fixed-final VisA runs. This schedule is retained for comparability rather than changed for speed.
